# Distinctive UI

## Proceso obligatorio

1. Inspecciona el proyecto:
   - framework y librerías;
   - componentes existentes;
   - estilos, tokens, fuentes e imágenes;
   - público y propósito del producto.

2. Antes de escribir código, define brevemente:
   - concepto visual;
   - personalidad de marca;
   - jerarquía tipográfica;
   - paleta funcional;
   - elemento distintivo;
   - comportamiento responsive.

3. Si falta identidad visual, elige una dirección coherente:
   - editorial;
   - técnica/industrial;
   - minimalista cálida;
   - brutalista;
   - retrofuturista;
   - institucional contemporánea.

   No combines varias direcciones sin justificación.

4. Implementa usando:
   - componentes reutilizables;
   - HTML semántico;
   - tokens de diseño;
   - estados interactivos completos;
   - accesibilidad;
   - responsive design.

5. Revisa el resultado:
   - ¿Podría pertenecer a cualquier producto?
   - ¿Hay una decisión visual memorable?
   - ¿La jerarquía guía correctamente al usuario?
   - ¿Se eliminaron adornos sin función?
   - ¿Los estados y tamaños pequeños están resueltos?

## Restricciones

- No inventes un design system nuevo si el proyecto ya posee uno.
- No reemplaces contenido específico por copy genérico.
- No agregues dependencias sin comprobar que sean necesarias.
- No sacrifiques usabilidad para conseguir originalidad.

Consulta `references/design-system.md` cuando exista.
